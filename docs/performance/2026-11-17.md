# Microgen 0.6 performance measurements

Compared0.5 (4b3e15f) with0.6 working renderer/rule changes. Godot4.6.3, Linux,1280x720, Mesa software OpenGL. Each displayed run measured600frames after warmup. Synthetic dense scene:28 durable r65 stationary enemies, level8 player, six rank3 organs/three synergies, four clones, six initial fields plus trails, nine remains and16pickups. This is an identical workload comparison, not physical Android FPS.

| Metric | Before | After |
|---|---:|---:|
| World drawing CPU mean |32.329ms|18.790ms|
| Native drawing calls/frame |5464.7|1899.5|
| Simulation CPU median |2.121ms|1.838ms|
| Simulation CPU p95 |3.339ms|2.299ms|
| Simulation CPU mean |2.341ms|1.940ms|
| Final engine draw calls |6500|3415|
| Final rendered primitives |288330|114516|

The final660displayedframes (60warmup+600measurement) had no script/polygon triangulation errors. Desktop rendering CPU decreases41.9%; native drawing calls decrease65.2%. Headless simulation separate600-frame comparison: mean4.458→1.526ms. Eligibility early-out drives much of simulation improvement for large healthy enemies; it is not representative of a field full of edible tiny prey. Cached visual-contour sweep microbenchmark alone improved about2%, whereas fallback-contour queries improved38.5%.

Changes: six nearest visible enemies receive detailed tissue, others use existing24pointLOD; player keeps full visual anatomy. One soft nucleus, fewer granules/veins, no per-gland gradient textures, broad rooted appendages, simplified distant mouths/scars. Check capture eligibility before polygon queries; cache scaled contact polygon until body/HP/visualshape changes. Precompute valid convex fragment hulls instead of repeatedly drawing occasionally invalid concave pieces. All pull and collision displacement now integrates continuous velocities. Limit render loop to60FPS. No video generation.

Remaining: test physical Tecno POVA5 and profile GPU/CPU there. Compact terrain collider of the soft growing body remains a prototype limitation.
