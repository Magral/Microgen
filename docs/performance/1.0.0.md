# 1.0.0 performance comparison

Measured 18 November 2026 in Pavel's timezone. Baseline: immutable 0.11.0 `c56774adf1f0f7bd9dd88aad1423578018c7feef`. Candidate: frozen working-source copy for the 1.0 foundation, including the complete-recipe anatomy cache key. Later malformed-loadout validation, permanent collection-upgrade compatibility and menu/recovery refinements are outside this fixture's active paths. The report's worktree hashes were collected separately; they must not be treated as exact hashes of the frozen copy.

## Changes and limits

Concrete optimizations: reuse one normalized legacy snapshot when constructing research rows, bounded history and pending-result queues, and a full-recipe hash cache key instead of allocating an incomplete formatted anatomy key. The latter also fixes stale morphology when traits change under the same seed. Existing environment, anatomy, feeding and synergy caches remain.

**These measurements do not show an overall speedup.** Native timings are mixed and mostly slower; the capped scene is slower too. Menu construction improvements are not measured by this gameplay harness. Further Android profiling remains necessary; desktop timings are not Android FPS.

Godot 4.6.3, GL compatibility, 1280×720, Xorg dummy over TCP and Mesa llvmpipe software rendering. VSync-off was requested but unsupported by the driver. Paired native profiling ran sequentially with other native QA idle. Some short headless regression checks overlapped profiling, so CPU scheduling may affect timings. This is one pair, not a statistical confidence interval. HUD, audio mixing and menus are outside the harness.

## Reproduction

```sh
python3 tools/performance/run_profile.py --commit c56774adf1f0f7bd9dd88aad1423578018c7feef --output build/performance-100-baseline --native
python3 tools/performance/run_profile.py --output build/performance-100-final --snapshots build/performance-100-baseline --native
```

The runner instruments disposable copies. Raw simulation/native/worst logs and replay states are in these output directories; `build/performance-100-report.json` consolidates readings. On a host with stale Xorg locks, supply a fresh running display through `--display`. No videos.

## Ten-minute simulation

36,000 fixed 1/60 steps, seed 44, six ordinary rank-3 organs and four rank-3 adaptations, high HP, boss suppressed, movement changes every six simulated seconds, feedback consumed and pending levels cleared. This fixture does not select all new inherited traits. Unit and controller tests separately cover their runtime effects and save/restore behavior. Both runs reach the same 221 kills; this does not imply all populations are identical at every frame.

| Simulated seconds | Baseline mean step ms | Candidate mean step ms | Baseline static MB | Candidate static MB | Kills, both |

| 180 | 1.138 | 1.269 | 22.842 | 23.022 | 40 |

Mean step is the preceding interval, not the cumulative average. Static memory is the engine counter, not total process RSS. Candidate memory rises and settles rather than growing without bound within this ten-minute fixture; longer/device runs remain unmeasured.
