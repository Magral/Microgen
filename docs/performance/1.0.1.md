# 1.0.1 performance comparison

Baseline is immutable stable 1.0 `526922cdeb9f3378a0f0e57bf1dc3ef3dff536c2`. Candidate is a disposable frozen copy of this branch with native packed-array volume transforms and a bounded final-lighting cache keyed by the complete material, phase and quantized normal array. Later test-fixture and documentation edits do not affect the fixture. Measured 18 November 2026 in Pavel's timezone.

## Scope and limitations

The main screen now uses a dedicated fullscreen layout with no ScrollContainer. Its construction is simpler, but the gameplay harness does not measure menus. The renderer optimization retains the same contour resolutions, lighting formula, organs, effects, simulation and population caps. Lighting colors are reused only when all inputs match; a regression covers two actual colliding 32-bit hashes. Complete keys prevent incorrect reuse, and copies prevent caller mutation of cached arrays. The new cache is capped at 96 entries and increases memory moderately.

**Results are mixed; no overall speedup or Android FPS claim is supported.** The fixed saturated scene is about 2.6% faster in this pair; ordinary samples vary. A single pair cannot establish that this small difference exceeds scheduling variance. Visual quality was not deliberately reduced.

Godot 4.6.3, 1280×720, GL compatibility, Xorg dummy over TCP, Mesa llvmpipe software rendering. VSync-off requested but unsupported. Native profile passes ran sequentially with other native QA idle; short headless regression checks overlapped portions of profiling. Final full QA ran afterward. HUD, audio mixing and menus are outside the harness. There was no physical Android test.

## Reproduce

```sh
python3 tools/performance/run_profile.py --commit 526922cdeb9f3378a0f0e57bf1dc3ef3dff536c2 --output build/performance-101-baseline --native
python3 tools/performance/run_profile.py --output build/performance-101-current --snapshots build/performance-101-baseline --native
python3 tools/performance/run_profile.py --render-only --output build/performance-101-final --snapshots build/performance-101-baseline --native
```

The last native pass includes the full-key collision correction, replacing the earlier hash-only candidate. The second pass supplies the ten-minute replay; the production simulation was unchanged throughout. Raw logs and states are in those directories, consolidated readings in `build/performance-101-report.json`.
