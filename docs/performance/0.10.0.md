# 0.10.0 performance evidence

Measured November 17, 2026 against immutable 0.9.0 commit `ec09c90de394d2dd01c4c7f40b52f6253339ab83`. The candidate is a frozen copy of the integrated 0.10.0 simulation/world renderer before later inspector/menu text, layout, and indicator-placement refinements. Inspector/menu code is excluded from these benchmarks; indicator placement changes preserve the same draw budget. Production sources were never instrumented.

## Result and limits

This release adds combat attribution, reward cysts and visual interaction/damage cues, alongside cached enemy organ recipes, shared per-draw clone positions and cached build synergies. Measurements show added simulation cost and mixed native scene timings. They **do not establish an overall performance improvement**. The frozen capped scene adds 1.9% draw CPU and 4.3% full-frame median; its p95 is lower in this one run.

Godot 4.6.3; 1280×720; GL compatibility; requested VSync off (unsupported by this driver); uncapped engine; Xorg dummy; Mesa 25.0.7 llvmpipe LLVM 19.1.7 software rendering. Full-frame wall time includes fluid, optical planes, shaders and driver/software rasterization. Draw CPU excludes those shader/raster costs. HUD, minimap, development/reward menus and audio mixing are excluded. These are software-renderer counters, **not Android or hardware GPU FPS measurements**. Each workload is one sequential same-machine pair, with normal scheduling/rasterization variance. Candidate headless replay briefly overlapped separate visual QA; its timing therefore also has that scheduling limitation. Native baseline and candidate were run with other native QA idle.

## Reproduction and evidence

```sh
python tools/performance/run_profile.py --commit ec09c90 --output build/performance-010-baseline --native
# Freeze source in build/performance-010-candidate-source before candidate runs:
python tools/performance/run_profile.py --source build/performance-010-candidate-source --output build/performance-010-current
python tools/performance/run_profile.py --source build/performance-010-candidate-source --output build/performance-010-current --snapshots build/performance-010-baseline --render-only --native
```

The source copy excludes `.git`, `.godot`, `build` and ZIP files. Raw replay/native/capped logs, checkpoints and extracted JSON remain in those two output directories. `build/performance-010-report.json` consolidates both complete result sets, bounded-state checkpoint counts, error counts and all 36 captured production source hashes. The source manifest is `build/performance-010-candidate-source/profile-source-hashes.json`. No videos were recorded.

The replay is 36,000 steps at 1/60 (ten simulated minutes), seed 44, six ordinary rank 3 organs/four rank 3 adaptations, high HP, profiling-only boss suppression and movement changes every six simulated seconds. Pending levels are cleared and UI/audio event queues consumed every step. Reward choices are not claimed; no quality/evolution is applied. This fixture does not benchmark upgraded quality/evolution builds or menu interactions.

Both native versions restore the exact same baseline 0/180/360/600 checkpoints. Each has 60 warmup frames and 180 draw samples while simulation continues at fixed 1/60. Missing effects rebuild during warmup; water wakes depend on real frame duration. Counts at the measured native endpoints match for enemies, fields, remains and effects, but this is a paired starting-scene comparison, not a frozen identical-frame capture. Cold terrain/cache construction is outside warmed timing.

Combat history has a 32-entry cap, source aggregation has 32 named buckets plus an overflow bucket, damage markers have a six-entry cap, cysts have a 12-entry defensive cap, and a run creates at most six map/two elite reward tokens. The fixture leaves three rewards queued. It does not exercise repeated reward selection. Existing scene caps remain 28 enemies/96 remains. Enemy organ recipes are keyed by identity and kind/variant/traits signature, pruned against living enemies, reset on simulation change and defensively cleared above 256 entries. Clone positions are calculated once per world draw and shared across effects; synergies rebuild only when the public organ/adaptation dictionaries change hash. These reduce repeated construction; the package timings above include new work and do not isolate a cache speedup.

Audio uses 11 precomputed PCM samples, six event voices and one persistent movement-loop voice. Movement adjusts gain/pitch rather than synthesizing/retriggering samples per frame; event playback is globally limited to one trigger per 0.4 s with additional per-kind intervals. This is a source-level resource bound; the profiling harness consumes feedback without mixing sound, so it makes no audio CPU or subjective audio-quality claim.
