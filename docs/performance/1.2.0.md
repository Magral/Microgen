# 1.2.0 performance and stability profile

Measured 18 November 2026 against immutable 1.1.0 baseline `a5c5177`. Godot 4.6.3, Linux container, Xorg dummy display, Mesa llvmpipe, same seeded ten-minute fixed-step replay and the same saved checkpoints for the renderer. These are desktop GDScript CPU measurements, not Android FPS. The run advances simulated time and counts game steps; it does not claim ten minutes of wall time.

The release adds fast paths for ordinary organs: build power avoids specialization, temporary-mutation, and endless-rank calculations unless the equipped organ uses them; organism painting skips catalog lookups for empty specialization data. No entity, effect, or organ caps were reduced.

## Ten-minute simulation replay

Seed 44, six rank-3 organs, four rank-3 adaptations, high health, boss disabled for profiling, 36,000 fixed 1/60 steps. Later enemy/remains/pickup counts diverge because kill outcomes change; compare each stage as a sampled workload rather than identical trajectories.

| Simulated seconds | 1.1.0 mean step ms | 1.2.0 mean step ms | 1.1.0 p95 ms | 1.2.0 p95 ms | Static memory MB 1.1.0 → 1.2.0 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 180 | 2.743 | 2.108 | 4.969 | 3.784 | 23.71 → 23.75 |
| 360 | 3.105 | 2.897 | 5.880 | 4.691 | 23.71 → 24.05 |
| 540 | 3.106 | 3.072 | 5.880 | 5.059 | 23.71 → 24.05 |
| 600 | 2.451 | 3.206 | 4.159 | 4.769 | 23.52 → 23.86 |

The candidate has lower mean and p95 step time at 180–540 seconds, while the 600-second sample is slower. Memory stays near 24 MB in the simulation harness without a steadily rising trend. Because later sample workloads differ and there is only one pair, these results support the targeted fast-path change but do not establish an overall long-session speedup. The slower final sample remains a follow-up optimization target for later work.

## Same-checkpoint native world draw

Each snapshot is warmed up and measured on the same software renderer. The container's VSync request is unsupported; absolute frame time is dominated by llvmpipe and should not be read as device performance.

| Snapshot seconds | 1.1.0 draw mean ms | 1.2.0 draw mean ms | 1.1.0 frame p95 ms | 1.2.0 frame p95 ms | Static memory MB 1.1.0 → 1.2.0 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 19.86 | 26.97 | 102.63 | 149.45 | 40.45 → 40.81 |
| 180 | 56.49 | 56.67 | 220.52 | 199.14 | 44.87 → 45.24 |
| 360 | 37.30 | 36.98 | 172.16 | 174.46 | 48.24 → 48.61 |
| 600 | 75.70 | 61.78 | 238.01 | 201.82 | 50.15 → 50.52 |

This renderer pair is mixed: 180 and 600-second draw p95 are lower, while the initial warm snapshot and 360-second p95 are higher. Therefore the release does not claim a blanket rendering improvement. The ten-minute candidate reached 23 enemies, 27 fields, 29 remains and 10 effects; no simulation caps were lowered.

## Verification and limits

The full local CI runner passed, including headless logic, touch input, native family UI, evolution and mutation visuals, render caching, and preview captures. Godot resource import and whitespace checks pass. Native Android export, APK signature, and physical-device battery/FPS are not measured locally: this workspace has no Android SDK or physical Android device. GitHub Actions remains the release gate for the signed APK and manifest.
