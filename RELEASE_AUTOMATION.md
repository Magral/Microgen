# Автоматизация стабильных релизов Defold

Релизы создаются в репозитории `Magral/Microgen` через GitHub Actions. Личный токен не требуется: workflow использует ограниченный для данного репозитория `GITHUB_TOKEN`.

## Закрытая сборка для проверки на устройстве

На рабочей ветке `preview/defold` корневой `release-request.json` всегда остаётся выключенным. Закрытая сборка по маркеру `[device-acceptance-defold]` предназначена для отдельной проверки без публикации:

```json
{"publish": false, "version": "1.5.15"}
```

Чтобы получить подписанный кандидат для установки поверх 1.5.14, отправить коммит в `preview/defold` с маркером `[device-acceptance-defold]`. После успешной Android-проверки и Linux smoke workflow загрузит внутренний артефакт `Microgen-Defold-1.5.15-Poco-X8-Pro-Acceptance` сроком на 14 дней. В нём находятся APK, SHA-256 и сведения о подписи и сборке.

Этот артефакт доступен только как вложение CI: он не создаёт тег, GitHub Release или публичную публикацию. Задание `publish` для `preview/defold` не запускается. До подтверждения установки и сохранности прогресса на Poco X8 Pro не создавать ветку `release/defold-1.5.15` и не включать публикацию.

## Как запустить релиз

1. Подготовить версию в `prototypes/defold/game.project` и заметки в `prototypes/defold/RELEASE_NOTES.md`.
2. Создать ветку `release/defold-<версия>` от проверенного кандидата.
3. Добавить в корень ветки файл `release-request.json`:
   ```json
   {"publish": true, "version": "1.5.15"}
   ```
4. Создать коммит этого файла с маркером `[publish-defold-release]` в сообщении.

Исключение для 1.5.15: 28 ноября 2026 года пользователь прямо разрешил публичный выпуск до ручной проверки на Poco X8 Pro, поскольку ему нужно получить обновление на телефоне. Поэтому релизная ветка создаётся от проверенного кандидата, а `publish: true` включает только этот выпуск. Публикация всё равно заблокирована до успешного полного CI. После публикации пользователь проверяет автообновление поверх 1.5.14 и сохранность прогресса на Poco X8 Pro. Для последующих версий ручная приёмка остаётся обязательной, если пользователь отдельно не распорядится иначе.

Workflow проверит совпадение версии и ветки, соберёт Android ARM64 APK, проверит подпись и идентификатор пакета, выполнит Linux smoke-проверки, создаст тег и стабильный релиз. Публикация происходит только после успешной сборки. Предварительные APK остаются внутренними артефактами CI.

Запуск с обычной ветки `preview/defold` не публикует релиз. Для следующего выпуска нужно использовать новую версию и новую релизную ветку.
